# WebLogcat 0.2 验收记录

日期：2026-10-27；实机：Pixel 10，Android 17 / API 37。验证 APK 使用 compileSdk / targetSdk 36、minSdk 26。设备时钟与电脑时钟不同；筛选的 `age` 使用手机时间。

| 项目 | 结果 |
| --- | --- |

| 缓存与虚拟滚动 | 受控日志压力测试达到 50,000 条，估算 31,170,632 字节，淘汰 6,087 条，采集仍存活；浏览器只渲染可见区域。独立 Java 测试也覆盖条数及 32 MB 两个边界。实际持续运行中也观察到 32 MB 上限触发淘汰。 |
| 导出 | 过滤导出和全部缓存导出的文本内容已分别核对。手机 Chrome 通过局域网 HTTP 下载时显示不安全下载提示，用户手动选择保留；实际下载的 714 字节文件包含测试标记和完整堆栈，见 `v02-android-download.json`。导出弹窗另提供复制内容。 |
| 手机端实际拔线 | 早期 READ_LOGS 方案已实测拔线后继续采集，见 `RESULTS.md`。0.2 本次实机验证了不依赖 ADB 转发的局域网访问，但没有对 0.2 再次物理拔线。 |

大批量测试中使用了错峰补充输入，手机 Logcat 的源缓冲及限流不保证记录源侧没有丢失。应用的 32 MB 是字段字符串与固定开销的保守估算预算，不是整个 Android 进程或浏览器的物理内存上限。

完整业务功能和静态网页资源在最终构建与实机安装后复核。根据后续反馈，最终 APK 增加了 READ_LOGS 与全设备日志访问验证两层启动门槛。独立测试源 APK 已卸载，本机代理已停止。WebLogcat 服务保留运行，端口已恢复为 8765，测试下载文件由用户选择保留。

## 后续权限门槛回归

- 撤销 READ_LOGS 后，界面提示授权，启动按钮不打开端口或二维码；以应用 UID 直接调用服务入口后，服务也立即退出。
- 授予 READ_LOGS 后，系统一次性确认弹窗出现前端口保持关闭。点击拒绝后，端口始终关闭、二维码隐藏；60 秒验证超时后服务停止。
- 重试并允许后，确认能读取其他 UID 的 main 日志，服务才开放端口；随后跨 UID 采集与 8765 / 8877 端口切换通过。
- 对话框未确认、拒绝或未观察到可用的其他 UID 日志时无法区分具体原因，统一等待最多 60 秒后提示重试。系统日志极少时可能发生保守超时。
- 最终安装 APK 与交付文件哈希一致；已重新解码二维码并核对网页资源，见 `v02-final-build.json`。

## 静态检查限制

尝试执行 Android Lint，AGP 9.0.1 的 Lint 在分析 Gradle Kotlin 脚本时因 `findFirCompiledSymbol` 内部异常崩溃，因此没有完整的 Lint 通过结果。构建、Node 查询/堆栈测试、Java 缓存测试和上述实机检查均通过。相近工具问题见 [Android Issue Tracker](https://issuetracker.google.com/issues/462288595)。

## 已知边界

- 全设备日志读取需要设备允许 READ_LOGS，并可能需要前台的一次性系统确认；后台重建采集进程可能被系统拒绝。
- 进程事件过期、共享 UID 或系统限制造成归属不明确时显示未知；不猜测包名或进程。
- 正则使用 JavaScript RegExp；堆栈归组使用相邻 PID/TID、标签和时间启发式，不保证识别所有日志格式。
- 日志流和访问链接使用局域网 HTTP。Chrome 可能提示下载不安全，可选择复制导出文本。
